#+title: 异步I/O

异步I/O 从io_uring 的引入(2019年) 才开始变得真正可用

-----
* io_uring
  io_uring 只能说未来可期, 但先阶段(2026年) 还不是很推荐.
  io_uring 被认为风险太高, 被很多linux 发行商默认禁用

* 同步I/O, 异步I/O
  同步I/O 的耗时大头是"等待"本身, 线程被挂起, 时间花在睡眠和上下文切换上;
  异步I/O 的耗时大头是"管理开销", 时间花在提交请求、维护队列、处理完成事件上.


  同步I/O 的耗时公式大致是: 设备物理延迟 + 调度等待 + 上下文切换 + 数据拷贝
  异步 I/O 总耗时公式大致是: 提交开销 + 设备/内核处理时间 + 完成收割开销


  综上,
  1. 高并发、可批量化的操作下, 异步I/O 的"管理开销"成本会被摊薄, 此时会优于同步I/O 的上文下切换与逐次系统调用
  2. 大操作且I/O是瓶颈时, 异步I/O 在内核中处理, 避免占用工作线程, 优化同步I/O 的阻塞等待; 但若使用缓冲I/O, 前台数据拷贝成本可能使收益打折


  #+attr_shortcode: info
  #+begin_hint
  直接 I/O: 磁盘 →(DMA)→ 用户缓冲区, CPU 不参与搬运
  缓冲 I/O: 磁盘 →(DMA)→ 页缓存 →(CPU 拷贝)→ 用户缓冲区，多了一次软件拷贝
  #+end_hint

  #+attr_shortcode: info
  #+begin_hint
  页缓存到用户缓冲区的拷贝确实由内核代码执行, 但执行这段内核代码的上下文, 可能就是发起 I/O 的那个用户线程
  #+end_hint
