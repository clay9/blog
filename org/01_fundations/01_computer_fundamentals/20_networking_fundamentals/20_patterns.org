#+title: 网络编程模式

Reactor: 同步模式; 依赖I/O 多路复用机制
Proactor: 异步模式; 依赖异步I/O
-----
* Reactor 流程
  以读为例:
  1. 应用向Reactor 注册"读就绪"事件及对应Handler
  2. Reactor 通过epoll 等待事件
  3. fd 可读时, Reactor 调用Handler
  4. Handler 执行read, 拿到数据, 处理业务
  5. 再注册下一次事件
-----
* Proactor 流程
  以读为例:
  1. 应用发起异步读, 把用户缓冲区地址, 大小告诉内核
  2. 应用立即返回去做别的事情
  3. 内核执行读操作, 把数据写入用户缓冲区
  4. 操作完成, Proactor 调用Completion Handler, 数据已经在缓冲区了, 处理业务
  5. 发起下一次异步操作
-----
* 关键对比
  |           | Reactor             | Proactor           |
  |-----------+---------------------+--------------------|
  | 通知时机  | 就绪时              | 完成时             |
  | 谁执行I/O | 用户线程            | 内核               |
  | I/O 模型  | 同步                | 异步               |
  | 数据拷贝  | 用户操作read 完成   | 内核写入用户缓冲区 |
  | 典型实现  | epoll + 非阻塞I/O   | io_uring           |
  | 代表框架  | Redis, Nginx, Netty | Asio               |


  #+attr_shortcode: info
  #+begin_hint
  Reactor、Proactor 是设计模型, 与底层I/O 机制并非一一绑定.
  Reactor 天然对应就绪通知(同步I/O), Proactor 天然对应完成通知(异步I/O), 但Proactor 可以用Reactor 来模拟实现, 比如Asio.

  Asio 在Linux上就是如此: 设计上是Proactor, 底层却可能跑在epoll + 非阻塞I/O 之上
  #+end_hint
