#+title: 基础概念


* TCP/IP四层模型
  从高到底依次是:
  1. 应用层
     Http, DNS, FTP 协议都在这一层
  2. 传输层
     核心是 TCP 和 UDP
     它负责把数据从一台机器的某个进程, 送到另一台机器的某个进程.
     端口号就在这一层起作用
  3. 网络层
     核心是 IP 协议
     它负责把数据包跨越不同网络路由到目标主机, 只管“尽力送到”, 不保证顺序和可靠性
  4. 链路层
     处理网线、网卡、物理信号这些底层细节
-----
* TCP/UDP 协议
  TCP 像是打电话, 需要先接通, 并且保证每句话都能听清楚
  UDP 像是寄信, 直接扔出去，对方可能收到, 也可能没收到

  TCP 传输控制协议
  1. 面向连接: 通信前必须先建立连接(三次握手), 结束后断开 (四次挥手)
  2. 可靠、有序: TCP 保证数据不丢, 不重, 按顺序到达. 如果丢了, 它会自动重传
  3. 字节流: 像是一根水管, 数据源源不断流过来, 没有消息边界.
     所以需要自己在应用层设计"一条消息结束"


  UDP 用户数据报协议
  1. 无连接: 不需要握手, 想发就发
  2. 不可靠: 不保证送达, 不保证顺序, 也不自动重传
  3. 数据报: 保留消息边界. 发一个包, 对方收到的就是一个完整的包 (或者什么都没收到). 单个包大小通常受限制

-----
* IP 协议
  它负责把数据包从一台主机送到另一台主机, 但只承诺“尽力而为”, 不保证送达、不保证顺序、也不保证不重复

  主要负责:

  1. 逻辑寻址: IP 地址
     IP 地址标识一个网络接口
  2. 路由与转发
     IP 协议根据路由表决定一个数据报下一跳去哪. 路由由内核和网络设备完成, 对应用层是透明的
  3. 分片与重组
     链路层对单帧大小有限制(MTU). 如果一个IP 数据报超过MTU, IP 层会把它分片, 到达目的地后再进行重组.
     UDP 发送过大的数据报会触发IP 分片, 任一分片丢失整个数据报就废了, 所以实践中UDP 单报控制在MTU 以内
