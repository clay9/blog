#+title: Socket

* Socket
  Socket 是内核提供的、位于传输层与应用层之间的编程接口.
  它把 TCP/UDP 等传输层协议的能力抽象为"通信端点", 让应用层用类似文件读写的方式收发数据, 而无需直接操作协议栈内部状态.
  它简化了应用层使用传输层的代码

  #+attr_shortcode: info
  #+begin_hint
  Socket 只是简化了传输层的代码使用, 但传输层的问题还是需要自己处理:
  - TCP 字节流没有消息边界, 需应用层自己设计分隔
  - TCP 连接可能静默断开, 长连接需要心跳保活
  - UDP 不保证送达和顺序, 需应用层自行处理
  #+end_hint


  #+attr_shortcode: info
  #+begin_hint
  一个Socket 端点由(IP 地址, 端口号, 协议类型) 唯一确定.
  #+end_hint


  #+attr_shortcode: info
  #+begin_hint
  TCP 静默断开:
  TCP 协议本身容错。没有主动关闭或异常重置且无数据发送时, 内核不主动探测对端, 空闲连接理论上可永久保持
  中间设备(NAT、防火墙、负载均衡器)为省资源维护会话表并设空闲老化超时. 超时即删表项, 通常不通知两端
  结果: 本地 socket 状态正常、无报错, 但下一次 send 的数据到不了对端 —— 路径设备已不认得这条连接

  所以需要心跳保活, 探测异常并清理死连接.
  #+end_hint


* Socket 启发
  通过Socket函数可以体会 Linux 一起皆fd 的思想:

  - socket() 在进程文件描述符表中占一个槽位, 返回fd. 内核同时创建对应的Socket 对象.
  - bind() 给Socket 端点填上本地 IP 和端口
  - 客户端 connect() 时内核自动分配源端口并绑定本机 IP
    所以客户端一般不需要 bind(), 除非要指定固定源端口/IP
  - accept() 会新建一个连接 fd, 和监听 fd 是两个不同的 fd
  - recv()/send() 在接口风格上和 read()/write() 一致
  - close() 因为是 fd, 关闭即减少引用计数, 归零时释放 Socket 并触发 TCP 挥手
  -----
* Socket API 问题
  1. 默认阻塞模型
     每个可能等待的操作都会阻塞所在线程
     - accept() 等待新连接时阻塞
     - connect() 等待握手完成时阻塞
     - recv()/send() 等待数据可读/可写时阻塞

     后果: 一个线程同一时刻只能服务一个连接
-----

* Socket API 问题解决方案
  可能的解决方案有:

  1. 设置 Socket fd 为非阻塞 ❌ 不推荐
     单纯把fd 设置为非阻塞, 会陷入忙轮询(busy polling).
     程序只能在一个循环里不断调用recv, 检查状态, 这会让CPU 空转, 浪费大量事件
     另外非阻塞 connect 返回 EINPROGRESS 后, 仍需事件通知机制, 才能知道连接何时完成
  2. 多线程, 多进程 ❌ 不推荐
     在连接数增加时, 线程/进程的资源和上下文切换成本会急剧上升, 经典的C10K 问题来源
  3. 非阻塞I/O + I/O 多路复用 ✅ 主流方案
     同样是把fd 设置为非阻塞, 但是把监控交给 epoll 这类机制统一监视, 而不是busy polling
     当epoll 通知fd 就绪时候, 再去进行处理
  4. 异步I/O  ✅ 更彻底的方案
     应用提交完整的I/O 操作给内核后立即返回, 内核在操作完成的时再通知应用.
     - 消除了"事件通知 + 手动发起读写" 之间的间隙;
     - 同步I/O 还需要自己read() 数据到缓冲区; 异步I/O由内核负责把数据拷贝到缓冲区

  #+attr_shortcode: info
  #+begin_hint
  I/O 多路复用中, 必须设置I/O 为非阻塞.

  1. 阻塞 fd 调用recv:
     - 有数据: 读走数据, 返回
     - 没数据: 阻塞线程, 直到有数据、对端关闭或出错才返回
  2. 非阻塞 fd 调用recv:
     - 有数据: 读走数据, 返回
     - 没数据: 立即返回-1, errno = EAGAIN


  如果fd 是阻塞的:
  1. 缓冲区还有数据时, recv() 正常返回, 循环继续
  2. 缓冲区读空时, 阻塞线程


  所以多路复用场景下, 必须设置I/O 为非阻塞的
  #+end_hint


  #+attr_shortcode: info
  #+begin_hint
  I/O 多路复用是"就绪通知"
  I/O 多路复用是同步操作, 它只告诉应用层某个fd 可以读写了, 实际的读写操作仍需要自己调用read/write 来完成. 对应的是Reactor 模式
  且主要面向网络I/O.

  异步I/O 是"完成通知".
  是一个异步操作, 把一个完整的操作(比如从fd读取4KB到这块缓冲区)提交给内核, 内核在操作真正完成时才通知你. 对应的是Proactor 模式
  它同时统一了网络和磁盘I/O
  #+end_hint
