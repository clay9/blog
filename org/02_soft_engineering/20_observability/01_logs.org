#+title: Logs

* Logs 字段
  如果把一条日志比作一张“快递单”, 那么这些字段就是收件人、寄件人、运单号和备注.
  只有字段规范统一了, 后端的日志平台（如 Loki、ELK）才能高效地做索引、过滤和告警

  | 纬度           | 字段名称    | 含义                              | 收集方式   |
  |----------------+-------------+-----------------------------------+------------|
  | 基础设施       | timestamp   | 时间戳(带时区)                    | spdlog     |
  |                | level       | 日志级别                          |            |
  |                | service     | 应用名 ( 不是业务架构中的service) | 日志收集器 |
  |                | env         | 运行环境 ( 待定)                  | 日志收集器 |
  |                |             | 防止测试日志与生产日志混淆        |            |
  |                | host/pod    | 物理主机名/k8s pod                | 日志收集器 |
  |                | logger      | 模块名( 对应业务架构中的 service) |            |
  |                | tread       | 线程名                            | spdlog     |
  | 链路追踪       | trace_id    | 全链路追踪ID                      |            |
  |                | span_id     | 当前方法/RPC 调用的子SpanID       |            |
  | 业务上下文     | user_id     | 用户唯一标识                      |            |
  |                | client_ip   | 客户端真实ip( 待定)               |            |
  | 核心内容与异常 | message     | 人类可读的简明描述                |            |
  |                | code/error  | 错误码                            |            |
  |                | stack_trace | 异常堆栈信息                      |            |

* 字段: logger
  logger 字段根据业务模块来设计, 每个模块拥有自己的logger.
  它提供了日志的 模块视角

  推荐的设计:
  1. 底层库( 如果是自己维护的)
  2. Service/Module: 业务模块
  3. Server: 基础库应该使用Server 的logger
