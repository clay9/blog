#+title: 可观测性

* 背景介绍
  随着软件系统从单体架构逐渐演进为分布式架构, 系统内部复杂度不断增加. 一个请求可能经过多个服务、线程、任务队列、网络连接、缓存和数据库, 系统的运行状态越来越难以通过单一组件的监控来全面了解.

  传统监控逐渐暴露出以下不足:

  1. 难以理解系统内部状态: 传统监控主要关注 CPU、内存、网络等基础指标, 难以反映系统内部的执行过程和组件间的交互情况.
  2. 难以发现未知问题: 传统监控依赖预先定义的监控指标和告警规则, 难以发现未预料到的异常和潜在问题.

  可观测性正是为了解决这些问题, 通过 Metrics、Logs、Traces 等数据, 从不同维度描述系统的运行状态, 帮助开发人员全面了解系统行为, 实现故障发现、问题定位和性能分析.
-----
* 概念
  1. Logs: 日志, 记录系统运行过程中发生的事件, 用于了解具体发生了什么, 例如错误信息、异常堆栈和业务执行记录
  2. Metrics: 指标, 通过数值和时间序列描述系统的运行状态, 用于分析系统性能和资源使用情况, 例如 CPU 使用率、请求数量、错误率和响应延迟.
  3. Traces: 链路追踪, 记录一次请求在系统中的完整执行路径, 用于分析组件间的调用关系和各环节耗时, 帮助定位性能瓶颈和故障位置
