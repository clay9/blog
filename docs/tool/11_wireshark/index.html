    Protocol 协议#

    OSI 七层模型

    层级英文主要作用典型协议/应用举例说明
    7应用层 (Application Layer)提供用户和应用程序的网络服务接口HTTP, FTP, SMTP, DNS, MQTT浏览器访问网页、邮件客户端收发邮件、IoT 设备通信
    6表示层 (Presentation Layer)数据格式化、加密/解密、压缩/解压TLS/SSL, ASCII, JPEG, MPEGHTTPS 加密传输、图像或视频格式转换
    5会话层 (Session Layer)建立、管理、终止会话/连接SIP, NetBIOS, RPC视频会议建立会话，数据库客户端维持连接
    4传输层 (Transport Layer)端到端的数据传输，提供可靠或不可靠服务TCP, UDP, QUICTCP 可靠传输（重传、排序），UDP 流媒体传输
    3网络层 (Network Layer)路由选择和逻辑寻址IP, ICMP, ICMPv6, IGMPIP 地址路由，Ping 测试，组播管理
    2数据链路层 (Data Link Layer)局域网内帧传输，物理地址管理，差错检测Ethernet, Wi-Fi (802.11), ARP, PPPMAC 地址通信，交换机转发帧，ARP 地址解析
    1物理层 (Physical Layer)实际传输比特流，定义物理介质和电气特性光纤, 网线, 无线电信号网线传输比特，Wi-Fi 信号发射，光纤信号传输

    OSI 七层模型只是指导作用(建筑蓝图), 现在网络实际是TCP/IP五层, 合并了5,6,7层

    数据封装过程:

    层数据单位说明
    应用层Data（应用数据）例如 HTTP 请求、DNS 查询
    传输层Segment / DatagramTCP 报文段或 UDP 数据报，包含端口号、序列号等
    网络层PacketIP 数据包，包含源 IP/目的 IP 等信息
    数据链路层Frame（帧）在局域网中传输的数据单位，包含源 MAC/目的 MAC、类型、CRC 等
    物理层Bits（比特流）真正通过网线/光纤/无线信号传输的 0 和 1

    1. 应用层的Data (比如文本,图片或视频)被传输层封装为Segment/Datagram
      Segment/Datagram本身不包含IP地址.

    2. 网络层把Segment/Datagram打包为Packet

    3. 网络层从应用层拿到目标ip后, 根据本地路由表判断:

      • 目标在本地网络 -> 设定下一跳IP = 目标IP (发送给目标主机)
      • 目标不在本地网络 -> 设定下一跳IP = 路由器IP (发送给网关)

    4. 数据链路层拿到下一跳IP后, 获取对应的mac address

      • 如果ARP缓存中可以找到IP对应的mac, 则使用该mac
      • 如果ARP中未找到, 则发送ARP广播, 获取mac address

    5. 数据链路层封装网络packet为frame, 并发送到对应的mac地址
      数据链路层发送给交换机, 交换机发送给对应的mac address.
      因为是通过交换机发送, 所以这里就是为什么需要frame中设置源, 目的mac address

    6. *frame到了路由器后, 路由器在网络层查看IP 目的地址, 决定下一跳的IP
      数据链路层重新封装frame:
      源MAC = 路由器接口MAC
      目的MAC = 下一跳设备MAC
