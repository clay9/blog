    总览#

    1. 运行时检测分析
    2. crash后最好用的方法 core + gdb
    3. crash后次一级的方法 临终遗言

    运行时检测#

    Sanitizer家族已经取代Valgrind, 成为最常用的运行时检测(2026/8/1)

    Sanitizer全称主要检测问题常用场景
    ASanAddressSanitizer内存错误日常开发首选
    UBSanUndefinedBehaviorSanitizerC++未定义行为几乎总和 ASan 一起用
    TSanThreadSanitizer数据竞争、线程同步错误多线程程序
    MSanMemorySanitizer未初始化内存读取高安全要求代码
    LSanLeakSanitizer内存泄漏服务端、长期运行程序
    HWASanHardware-assisted AddressSanitizer内存错误（硬件辅助）ARM64、大型系统
    CFIControl Flow Integrity控制流劫持安全加固
    SafeStackSafe Stack栈攻击防护安全敏感程序

    常用的是开启ASan + UBSan + LSan.
    其他的无法同时全部开启

    crash: core + gdb#

    生产环境一般很难有core

    crash: 临终遗言#

    1. 生成环境backtrace -> raw数据(PC)
    2. raw数据 -> 提交给分析服务器处理

    分析服务器需要有程序的debug symbol信息, 这就要求生成程序的时候需要携带debug symbol信息.
    CMake中常见方案是使Release with debug 来生成程序, 而后剥离出程序的debug symbol信息

    backtrace 所在的handler 代码一定要简单. 因为此时程序已经崩溃了, 要保证在最低可用情况下, 留下临终遗言
